Origin & Motivation

01010101

Why Reed

  • Declarative dataflow applications accumulate dependencies between computations that developers otherwise track and re-synchronize by hand.
  • Production dataflow systems need a runtime that keeps many strongly typed pieces of state consistent with minimal orchestration code.
  • Reed factors that need into a standalone engine: developers express computations as transformations over state, and the runtime infers dependencies and propagates updates on its own.

The name

On a loom

The reed is a comb-like structure that aligns, separates and beats the warp threads into place as fabric is woven — it keeps many parallel threads synchronized without touching any single one directly.

In this engine

Reed organizes strongly typed pieces of application state the same way: it aligns dependencies between them, separates concerns by layer, and keeps every piece synchronized as the whole evolves.

Design Principles

02020202

Six principles

PrincipleCommitment
State-orientedComputation revolves around synchronized state, not direct calls between computations.
DeclarativeDependencies are described, never manually orchestrated.
IncrementalOnly the computations affected by a change are recomputed.
Event-drivenState evolves in response to events, not on-demand queries.
Strongly typedEvery artifact and every dependency is statically defined.
LayeredTransport, synchronization, computation and dataflow stay independent concerns.

Four layers, one direction

1 · Transport

How does information move? Delivers messages between nodes.

2 · Synchronization

What is the shared truth? Maintains one consistent state.

3 · Activation

What must be recomputed? Propagates change incrementally.

4 · Composition

How is computation described? Declares the dataflow graph.

Proposed Terminology

03030303

Three unsettled terms

  • The team's own notes mark Depot, Outpost and Parcel as still under evaluation — every other term (Node, Bus, Port, Message, Flow) is already considered stable.
  • Those three happen to borrow from logistics vocabulary, while the engine itself is named for a loom part. Aligning them to the same weaving metaphor gives the vocabulary one consistent source instead of two.

Renaming proposal

CurrentProposedRationale
DepotWarpThe threads held under tension on the loom — the authoritative shared state the runtime holds taut across every node.
OutpostHeddleThe cords that guide and lift individual warp threads — a node's synchronized, per-dependency interface into the Warp.
ParcelParcel (unchanged)Considered against Thread and Strand for metaphor coherence; retained because Thread collides with concurrency terminology the project must stay orthogonal to.

Discussion

Warp and Heddle close the vocabulary gap Depot and Outpost left open — one metaphor, end to end.
